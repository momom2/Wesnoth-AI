# Arm VG3 (2026-09-02): grounding on the gate's own frame +
# measured lambda0 + checkpoint continuation metadata

User rulings after the VG2 postmortem: (1) "let the label match
the states, no matter how insignificant the difference may seem";
(2) lambda's first value from the measured movement's upper
spread, relaxed as confidence improves; (3) every checkpoint
carries continuation metadata (the controller's latest
recommended lambda and the paired-label estimates), the seed's
computed once and served to every arm that starts from it.

## Changes vs VG2 (docs/arm_vg2_leg_20260902.md)

- Capture point: STAGE-1 candidate evaluation sims -- the
  mover-frame PRE-FLIP boundary states batch_boundary_values
  grades (tools/turn_search.plan_turn `capture(boundary_sim)`).
  Both labels are derived at finalize from that state: hand the
  turn over, then (rollout) play to the end with the raw policy /
  (consistency) the production depth-H projection -- i.e. the
  gate's own stage-2 grade of that state. The trained input, the
  trust-region anchor and the dv measurement are now all on the
  frame the search reads.
- lambda0 measured: signal_profiler/run_label_calibration.py runs
  one production iteration at lambda=1 on a scratch copy and sets
  lambda0 = p90(dv)/delta (docs/design_constants.md).
- training_meta on every checkpoint ("vg2" block: lambda, delta,
  bias, sigma2, dv history, recipe fingerprint); MCTSPolicy
  restores it on load when the fingerprint matches, refuses loudly
  otherwise. The calibrated seed copy
  (seed_imit_tierb_start_vg3cal.pt) is the leg's --checkpoint-in.
