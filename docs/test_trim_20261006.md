# Test suite trim (2026-10-06)

User order: delete the tests whose time per unit of surface covered is
more than four times that of the 20th percentile, as an intuition for
keeping the most important tests, not a hard rule. Branch
`test/trim-suite`, cut from `main` at 0.14.0.

## The measure

Measured on CI (GitHub Actions, ubuntu-latest, Python 3.13, the Rust
wheel built from the commit), the full suite in both tiers:

- **Surface** of a test: the lines of project code it executes, each
  weighted by 1 / (the number of tests that execute that line), summed.
  A line only one test runs counts 1; a line every test runs counts
  almost nothing.
  - Python: coverage.py 7.16.2, one context per test. A `.pth` hook
    starts coverage in every Python process, and a child process takes
    the running test's node id as its context, so the lines a test runs
    in the processes it starts are credited to it. Only lines inside
    function bodies count (module and class bodies run once, at
    import), and test code is not surface.
  - Rust: the crate built with `-C instrument-coverage`; its counters
    are written after every test and by every child process a test
    starts. Every executed line of `rust/wesnoth_core/src` counts.
  - Lines that run outside any test (collection, imports: 203 lines)
    weigh 0, since no deletion can lose them.
- **Time**: setup + call + teardown, the mean of two plain CI runs.
- **Ratio**: surface / time.

## Threshold and candidates

1,847 tests ran; the 54 that skip on CI (they need data outside git,
CUDA, a Wesnoth install or the Vast SDK) are not measured. They executed 36,856 lines: 31,108 Python
function-body lines and 5,748 Rust lines.

- 20th percentile of the ratio: **88.96** lines per second.
- Threshold, a quarter of it: **22.24**.
- Below it at once: 197 tests, 362.9 s of the 565.3 s the tests take.
- Elimination (remove the test with the lowest ratio, recompute every
  surface against the tests left, repeat until none is below): 190
  tests, 358.1 s. It keeps one of a group of tests that share their
  lines instead of deleting the whole group.

Every candidate was read. The elimination was then rerun with the kept
ones forced in, which flagged 6 more: 196 candidates in all. Decisions:
52 deleted, 13 slimmed, 131 kept (one of them moved to the slow tier).

Borderline rule: a candidate within 10% of the threshold (ratio 20.0
or more) is kept when it runs a line no other test runs or guards a
named past bug, and deleted otherwise. The threshold sits inside the
timing noise: the two samples of a test over 0.2 s differ by 21% of
their mean at the median, and taking the faster sample instead of the
mean changes the elimination by 8 tests.

## Limits of the measure

- Shell code and Python passed to `python -` are invisible; those
  tests were judged by hand.
- A module- or session-scoped fixture's lines and setup time are
  credited to the first test that uses it.
- A test of a copy, a source scan or a data check has no surface by
  construction; each was judged by what it guards.

## Reproduce

workflow), 387d611 (Rust coverage) and 175819d (the table:
`.github/trim/surface_table.py --db <python db> <rust db> --timing

removed at the branch's tip and stay in its history.
