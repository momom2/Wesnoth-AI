# Arm VG2 (2026-09-02): principled label mixture + value trust region

User ruling: no empirically tuned mixture weights ("Unconceivable!"),
no caps (bias that would need circumscribing). Every parameter of
the value-grounding design becomes a measurement.

## Design (shipped: commits 2514ebb, 99d247a)

Three label sources for the value head, each entering as its
negative log-likelihood under its own noise model:

- game outcome (real states) and rollout outcome (consulted
  states, raw-policy playout): +-1 -> categorical C51 loss, as
  before. Rollout states train at value_weight 1.0 (their NLL).
- search estimate (consulted states, depth-H projection): a
  SCALAR bootstrap -> Gaussian NLL of the head's MEAN prediction,
  (v - (z - b))^2 / (2 sigma2). No weight: its strength IS the
  measured precision.

b (systematic bias, the WYSIATI boundary optimism) and sigma2
(residual variance) are ESTIMATED by the learner every iteration
from paired labels -- the rollout subset is a prefix of the
consistency subset, so those states carry both (z_pair) --
  b = mean(z_search - z_roll)
  sigma2 = var(z_search - z_roll) - mean(1 - (z_search - b)^2)
(the rollout's own outcome noise subtracted), EMA 0.8 across
iterations. Global bias correction is a known simplification
(user: "fraught; suspect it first for future issues").

Trust region: lambda * (v - v_anchor)^2 on every consulted state,
v_anchor = the head's prediction at iteration start. lambda is not
a knob: dual ascent on the live dv_consult against trust_delta =
0.08 (2 C51 atoms = the search's measured decision resolution;
docs/design_constants.md) -- x2 above 1.5 delta, /2 below
delta/1.5, PPO adaptive-KL schedule. Starts at 1.0.

Rollout-label bias vs true search-play outcome: NOT measured (needs
rollouts from real states with known results; the harvest keeps no
sims). Assumed small; flagged.

  var(search - roll) = 1.050; rollout outcome noise 0.950
  sigma2_hat = 0.100    (a small difference of two large numbers:
                        the precision 1/sigma2 is uncertain by
                        ~2-3x; the trust region bounds the RATE so
                        the risk is under-learning, not collapse)
  head - search (raw) = +0.743; head - truth = +0.42: the HEAD is
                        the more biased party -- the acting-side
                        optimism the boundary_sum telemetry has
                        shown for a month -- and the search
                        estimate is closer to the rollout truth.
  Gaussian per-state gradient scale |gap_corr|/sigma2:
                        mean 4.5, p90 8.7

Reading: the bias-corrected labels sit at truth level and demand
the head come DOWN ~0.4 on consulted boundary states -- a coherent
correction, which is exactly what the trust region is for: it
spreads the move over iterations at <= 2 atoms per step instead of
letting it land in one.

## Result: K-collapse in ONE iteration (2026-09-02, 12:23 UTC)

    iter  K_med  et%   atk%  W/W/D    accepts/plan  shorten/plan  dv     lambda  head-truth
      0    12    7.6   20.6  14/10/0     0.154         0.097       0.312   3.90    +0.28
      1     1   21.1   14.4   7/15/2     0.646         0.582       0.128   6.26    -0.23

Iteration 0 trained at lambda=1.0 (the controller had no reading
yet) and let the consulted-state valuations move 0.31 -- the whole
+0.28 head optimism was corrected AND overshot to -0.23 in a single
iteration. Iteration 1's games then showed the TCS gate accepting
SHORTENING alternatives at 4x the rate (shorten/plan 0.10 -> 0.58,
accepts/plan 0.15 -> 0.65): end_turn candidates started winning
the gate, K median 12 -> 1. The trust region did reduce the NEXT
iteration's movement (dv 0.31 -> 0.13 at lambda 3.9) -- the
controller works -- but the damage was done in the unprotected
first iteration. Trainer stopped by hand at ~12:35 (the K-tripwire
would have fired at iteration 3); diagnostic TCS collapse probe
(seed vs the iteration-1 checkpoint, mover frame, project reval)
run on the box before teardown. Checkpoint:
/workspace/pins/vg2_iter1_2830204.pt (escrow tier-b/arm_vg2_20260902/).

    end_turn accepts  3/107     10/132

The head's valuation of the MOVER'S OWN end-of-turn position (the
pre-flip, mover-frame state stage 1 grades) swung by 0.71 -- more
than twice the 0.31 movement measured on the states that were
actually trained and anchored (the post-flip projection-pair
states). The trust region bounded the wrong frame: grounding
captures came from stage-2 projection pairs (post-boundary,
opponent to move), while the gate's stage-1 comparison reads the
pre-flip mover-frame state one flip away. The correction
generalized across that flip with amplification, contrast between
candidates collapsed 3x (0.086 -> 0.026), the projection re-grade
turned systematically positive, and end_turn / shortening
alternatives started clearing the gate.

Design error, fixable: capture, ground, anchor and dv-measure the
STATES THE GATE READS (mover-frame pre-flip boundaries, the
batch_boundary_values path -- exactly what the round-5 consult
probe hooked), not the projection pairs. A rollout from a pre-flip
state ends the turn and plays on, so the truth label is the same;
only the trained INPUT changes to the frame that matters. Plus
first-iteration protection: the controller's initial lambda must
come from the calibration harvest's own predicted movement, not
1.0 (the collapse horizon is one iteration).
